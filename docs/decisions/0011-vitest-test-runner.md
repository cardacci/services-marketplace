# 0011. Vitest as the test runner

- **Status:** Accepted
- **Date:** 2026-10-18
- **Supersedes:** the test runner choice (Jest) in [0008](0008-api-only-testing-first.md). The rest of 0008 (API only, test database, no frontend or browser tests yet) still applies.

## Context

ADR 0008 chose Jest because it was the NestJS default. NestJS 12 now generates projects as ES modules with **Vitest** and Supertest instead. Jest's ES module support is still experimental and needs extra configuration, or the API would have to go back to CommonJS.

## Decision

- **Vitest** runs the API unit tests (`*.spec.ts`) and e2e tests (`test/*.e2e-spec.ts`, own config), as generated by NestJS 12.
- **Supertest** stays for e2e tests.
- When frontend tests are added (0008), they also use Vitest, so the monorepo has a single test runner.

## Alternatives considered

- **Jest** — keeps 0008 as written, but means undoing the generated setup and fighting ES module support.

## Consequences

- Test code keeps the Jest-style API (`describe`, `it`, `expect`, `vi.fn()` instead of `jest.fn()`).
- Vitest runs through Vite, which also builds the web app: one transform pipeline and config style for both apps.
- Docs that mentioned Jest (`testing-strategy.md`, `overview.md`, `CLAUDE.md`, `README.md`) now say Vitest.
