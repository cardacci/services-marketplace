# Frontend conventions

## Structure

Feature-based folders (see `overview.md`). A feature owns its pages, components, API hooks and local state. Code shared by several features moves to `components/`, `lib/` or `stores/`.

## State

| Kind | Tool | Examples |
|---|---|---|
| Server state | TanStack Query | professionals, appointments, messages, notifications |
| Global client state | Zustand | session user, active mode (client / professional) |
| Local UI state | `useState` / `useReducer` | open dialogs, selected tab |
| Form state | React Hook Form | onboarding, appointment request |
| URL state | React Router search params | search filters, so results are shareable |

Rules:

- Never copy server data into Zustand. Read it from the query cache.
- Query keys come from a factory per feature: `appointmentKeys.list(filters)`, `appointmentKeys.detail(id)`.
- Mutations invalidate or update the related queries.
- Real-time events (Socket.IO) update the query cache with `queryClient.setQueryData`.

## API access

- One HTTP client in `lib/api.ts` (`fetch` wrapper with `credentials: 'include'`).
- Response types come from `@sm/shared`; never redefine them in the web app.
- API error `code` values map to Spanish messages in one place.

## Forms

- React Hook Form + `zodResolver` with the schema from `@sm/shared`.
- Show field errors under each field; server errors as a toast or form-level message.

## UI

- Tailwind CSS + shadcn/ui. Components in `components/ui/` are generated by shadcn and can be edited.
- Mobile first (`NFR-01`).
- UI copy in Spanish (Argentina), using the terms in `docs/product/glossary.md`.
- Accessible by default: labels on inputs, keyboard navigation, visible focus.

## Naming

- Components: `PascalCase.tsx`, one component per file.
- Hooks: `useSomething.ts`.
- Query hooks: `useProfessionalsQuery`, `useAcceptAppointmentMutation`.
- Pages: `SomethingPage.tsx` under `features/<feature>/pages/`.
